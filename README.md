# 숨쉬는길 (soomgil)

대전형 대기 위험 회피 내비게이션. 공공데이터로 대전의 꽃가루·미세먼지·폭염·오존을
실시간 분석하고, 풍향과 분지 지형의 대기정체까지 반영해 **상대적으로 안전한 이동 경로**를
안내합니다.

고등학생 창업 프로토타입 · 공모전 출품작

---

## 시작하기

```bash
npm install
npm run dev
```

http://localhost:3000

지금은 **예시 데이터(mock)** 로 동작합니다. 인증키 없이 모든 화면이 완전하게 돌아갑니다.

### 계절 강제 (시연용)

모든 페이지에 `?season=` 을 붙이면 그 계절 상황으로 화면이 바뀝니다.

| 계절 | 주소 | 상황 |
|---|---|---|
| 봄 | `/?season=spring` | 참나무 꽃가루 매우높음 + 황사 유입 |
| 여름 | `/?season=summer` | 폭염경보 + 오존 나쁨 |
| 가을 | `/?season=autumn` | 잡초 꽃가루 + 미세먼지 |
| 겨울 | `/?season=winter` | 초미세먼지 매우나쁨 + 한파 |

아무것도 붙이지 않으면 **오늘 날짜에 해당하는 계절**로 동작합니다.

## 실제 공공데이터로 전환하기

코드는 손대지 않습니다. `.env.local` 두 줄만 채우면 됩니다.

```bash
cp .env.example .env.local
```

```env
NEXT_PUBLIC_DATA_MODE=live
DATA_GO_KR_SERVICE_KEY=<공공데이터포털 일반 인증키(Decoding)>
```

키가 비어 있으면 `live`로 설정해도 자동으로 mock으로 떨어집니다. 시연 중 사고를 막기
위한 장치입니다. 실 API 호출이 실패해도 예시 데이터로 대체하고 콘솔에 경고를 남깁니다.

### 신청할 API 4종 (data.go.kr)

| 서비스 | 쓰는 곳 |
|---|---|
| 기상청_꽃가루농도위험지수 조회서비스 | 소나무·참나무(3~6월), 잡초류(8~10월) |
| 기상청_생활기상지수 조회서비스 (3.0) | 대기정체지수 |
| 기상청_단기예보 조회서비스 | 기온·습도·풍속·풍향 (체감온도 산출용) |
| 한국환경공단_에어코리아_대기오염정보 | 미세먼지·초미세먼지·오존 |

전환 전 확인할 항목은 코드 안에 `TODO(live)` 로 표시해 두었습니다.

```bash
grep -rn "TODO(live)" src/
```

주요 항목:
- `src/lib/api/endpoints.ts` — 오퍼레이션명을 기술문서와 대조
- `src/data/districts.ts` — `areaNo`·예보 격자 대조 (인접 구가 같은 격자를 공유하는 건 정상)
- `src/data/stations.ts` — 에어코리아 측정소가 현재도 운영 중인지 확인

### TMAP 보행자 경로 API (선택)

경로 안내를 **실제 도로 기반**으로 바꾸려면 TMAP 앱키가 필요합니다. 공공데이터포털과는
다른 사업자(SK Open API)라 별도로 발급받습니다.

1. [tmapapi.tmapmobility.com](https://tmapapi.tmapmobility.com) 회원가입
2. 앱 등록 → 앱키 복사
3. `.env.local` 에 추가

```env
TMAP_APP_KEY=<발급받은 앱키>
```

`NEXT_PUBLIC_` 을 붙이지 마세요. 브라우저에 노출되면 다른 사이트에서 남용해
호출 한도를 소진시킬 수 있습니다.

키가 없거나 호출이 실패하면 **격자 A* 근사 경로로 자동 전환**됩니다. 코드 수정은
필요 없고, 화면 상단에 지금 어느 엔진으로 계산된 경로인지 항상 표시됩니다.

### 호출량

스냅샷 1회에 21개 호출이 나갑니다. 데이터 발표 주기에 맞춰 서버 캐시를 걸어
개발계정 한도 안에 들어오게 해 두었습니다 (`src/lib/env.ts`).

| 대상 | 캐시 | 일 호출 |
|---|---|---|
| 꽃가루·대기정체 | 3시간 | 120 |
| 단기예보 | 1시간 | 96 |
| 기상특보 | 10분 | 144 |
| **기상청 합계** | | **360** |
| 에어코리아 | 20분 | 72 (한도 500) |

## 배포 (Vercel)

1. GitHub에 저장소를 만들고 푸시
2. [vercel.com](https://vercel.com) → New Project → 저장소 선택
3. 프레임워크는 Next.js로 자동 인식됩니다. 빌드 설정을 바꿀 필요 없습니다.
4. 환경변수는 실 데이터로 전환할 때만 넣습니다
   (`NEXT_PUBLIC_DATA_MODE`, `DATA_GO_KR_SERVICE_KEY`)
5. Deploy

`.env.local` 은 git에 올라가지 않습니다. **인증키를 커밋하지 마세요.**

배포 후 `src/config/site.ts` 의 `SITE.url` 을 실제 주소로 바꾸면 메타태그·사이트맵에
반영됩니다.

## 구조

```
src/
├─ app/                      라우트 12개 + /api/risk
├─ components/
│  ├─ layout/                Header · MobileNav · Footer · Container
│  ├─ home/                  히어로 · 문제해결 대비 · 대시보드 · 기능카드 · 공지
│  ├─ map/                   Leaflet 지도 (위험 지도 / 레이어 / 경로)
│  ├─ risk/                  등급 배지 · 지표 카드 · 지역 상세
│  ├─ chart/                 자치구 막대 · 시간대별 추이
│  ├─ route/                 경로 입력 폼 · 경로 비교
│  └─ account/               로그인 · 마이페이지 설정
├─ lib/
│  ├─ api/                   공공데이터 호출 계층 + getRiskSnapshot()
│  ├─ normalize/             원본 응답 → 도메인 타입
│  ├─ risk/                  계절 · 체감온도 · 점수 · 색 · 행정동 · 하천축
│  ├─ routing/               TMAP · 격자 A* · 경로 계획 · 행정동 매칭
│  └─ utils/                 KST 시간 · 포맷 · 바람 · 로컬 저장소
├─ mocks/                    API 응답 형태 재현 + 4계절 시나리오
├─ data/                     자치구 · 측정소 · 장소 · 공지 · GeoJSON
└─ config/                   지표 · 계절 · 레이어 · 사이트
```

핵심 진입점은 `src/lib/api/index.ts` 의 `getRiskSnapshot()` 하나입니다.
모든 화면은 이 함수가 돌려주는 `RiskSnapshot` 만 소비하며, mock인지 live인지 모릅니다.

## 계산 방식

```
지표 원단위값
  → ① 0~100 정규화 (4단계 경계값이 25/50/75에 오도록)
  → ② 계절 가중합            = 보정 전 점수
  → ③ 대기정체 보정 (최대 ×1.35)
  → ④ 0~100 클램프           = 최종 점수
```

②③④를 모두 남겨 화면에서 "대기정체로 +24.9% 상승"을 그대로 보여줍니다.

경로 안내는 여기에 **풍향 보정**(바람 불어오는 쪽이 더 나쁘면 가산)과
**하천축 보정**(갑천·유등천·대전천 주변은 확산이 좋아 감산)을 더합니다.

경로 자체는 두 가지 엔진 중 하나로 만듭니다.

| 엔진 | 조건 | 방식 |
|---|---|---|
| `tmap` | `TMAP_APP_KEY` 있음 | TMAP 보행자 경로 API로 실제 도로 폴리라인을 받아, 100m 간격 샘플링 + point-in-polygon으로 통과 행정동을 판정 |
| `grid` | 키 없음 / 호출 실패 | 대전 전역 약 550m 격자 위 A* 근사 경로 |

**위험도 계산은 두 엔진에서 완전히 동일합니다.** 경로 좌표만 다를 뿐
정규화·보정·노출량 계산은 같은 코드를 통과합니다.

TMAP은 대안 경로를 여러 개 주지 않으므로, 출발-도착 직선의 중점에서 좌우로 벌린
경유지 후보를 만들고 위험도 지도로 미리 걸러낸 뒤 상위 2개만 추가로 호출합니다
(요청당 TMAP 호출 3회).

자세한 내용과 한계는 서비스의 [이용안내](/guide) 페이지에 정리돼 있습니다.
